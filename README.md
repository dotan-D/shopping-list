# קניות — רשימה משותפת

אפליקציית PWA בעברית וב־RTL, מותאמת לטלפון. כל מי שפותח את האתר רואה ועורך **אותה רשימת קניות**. הוספה או סימון כנקנה מתעדכנים אצל שאר המשתתפים אוטומטית, בתוך עד כ־15 שניות כשהאתר פתוח, וגם בחזרה לאפליקציה או בלחיצה על ״רענון״.

הממשק נשאר HTML, CSS ו־JavaScript ללא build וללא תלויות npm. לשמירה בין מכשירים נוספה פונקציית Node.js ב־Vercel (`api/list.js`), ששומרת את הרשימה במסד Upstash Redis באמצעות HTTPS. המפתחות נשארים בשרת ואינם נשלחים לדפדפן.

## חיבור ב־Vercel

1. פתחו את הפרויקט **shopping-list** ב־Vercel ועברו ל־**Storage**.
2. בחרו **Create Database** (או **Connect Store / Browse Marketplace**, בהתאם למסך), ובחרו **Upstash Redis**. בחרו תוכנית מתאימה ובדקו את המחיר לפני אישור.
3. צרו מסד וחברו אותו לפרויקט. בחרו את סביבות הפריסה שצריכות גישה אליו — לפחות **Production**; כדי לבדוק PR Preview, חברו גם **Preview**.
4. בדקו ב־**Settings → Environment Variables** שנוספו אחד מצמדי המשתנים הבאים:
   - `KV_REST_API_URL` ו־`KV_REST_API_TOKEN`, או
   - `UPSTASH_REDIS_REST_URL` ו־`UPSTASH_REDIS_REST_TOKEN`.
   נדרש token עם הרשאת כתיבה. אין להדביק מפתחות בקוד או בצ׳אט.
5. פרסו את הקוד החדש. אם החיבור למסד נוסף אחרי הפריסה, בצעו **Redeploy** כדי שהפונקציה תקבל את המשתנים.
6. פתחו את **אותו קישור אתר בשני מכשירים**, הוסיפו מוצר באחד, וודאו שהוא מופיע בשני; סמנו אותו כנקנה וודאו שהוא מוסר בשניהם.

אין פקודת build או תיקיית פלט מיוחדת. Vercel מזהה את הקבצים הסטטיים ואת פונקציית ה־API. Python HTTP server בלבד אינו מספיק להפעלת השיתוף.

**הרשימה אינה פרטית:** אין התחברות. כל מי שיכול לפתוח את האתר יכול לקרוא ולשנות אותה. סביבות Preview ו־Production המחוברות לאותו מסד משתמשות באותה רשימה; לבדיקות נפרדות חברו מסד נפרד לסביבת Preview. הרשימה נשמרת במפתח `shopping-list:shared:v1` ללא תאריך תפוגה.

## שימוש

1. בוחרים קטגוריה ולוחצים על מוצרים להוספה, או מקלידים בשדה החיפוש ובוחרים השלמה מתוך הקטגוריה. אפשר להשתמש במגע או בחצים וב־Enter; Escape סוגר את ההשלמות.
2. ״אחר״ מאפשר להוסיף מוצר בטקסט חופשי בכל קטגוריה. הוספה של אותו שם משני מכשירים אינה יוצרת כפילות.
3. עוברים ל״הרשימה המשותפת״. סימון מוצר כנקנה מסיר אותו אצל כולם. אפשר גם למחוק בפח; ״ביטול״ מחזיר את הפריט האחרון שהסרתם.
4. ״רענון״ טוען מיד את הרשימה העדכנית מהשרת. פעולות מוצגות כהושלמו רק לאחר אישור מהשרת. במקרה של כשל בדקו את הרשימה לפני ניסיון נוסף; שמות מוצרים לא נזרקים משדה הטקסט בגלל כשל בשמירה.

הרשימה המקומית מהגרסה הקודמת נשארת ללא שינוי בדפדפן. תוצג הצעה **להוסיף אותה לרשימה של כולם**, ורק בלחיצה ייובאו הפריטים שטרם נקנו. הרשימה המשותפת היא מקור הנתונים הראשי; מטמון בדפדפן משמש רק להצגת העותק האחרון ללא אינטרנט. עריכה דורשת חיבור — אין שמירה מקומית שקטה או תור העלאה מאוחר שעלול להחזיר מוצרים שכבר נקנו. בעת חוסר חיבור או חוסר הגדרה של המסד מוצגת הודעה ופעולות העריכה מושבתות.

## קטלוג המוצרים ו־PWA

`catalog.js` מכיל 486 שמות מוצרים ייחודיים מתוך 487 שורות בקובץ `רשימת_מוצרים.xlsx`, בחלוקה ל־14 קטגוריות. הכפילות ״צ׳יפס קפוא״ אוחדה ושכיחויותיה חוברו. השמות נשמרו כפי שסופקו; השכיחות משמשת לסידור ההצעות. אין צורך ב־Excel בזמן הריצה.

הקטלוג, החיפוש והעותק האחרון של הרשימה זמינים ללא אינטרנט לאחר טעינה ראשונה והפעלת ה־Service Worker. שירות ה־API לעולם אינו נשמר במטמון ה־Service Worker או ב־CDN. התקנה למסך הבית דורשת HTTPS (או localhost בפיתוח). ב־iPhone: Safari ← שיתוף ← הוספה למסך הבית. בשינוי קובצי מעטפת או קטלוג עדכנו את גרסת המטמון ב־`sw.js`; Service Worker חדש מופעל לאחר סגירת חלונות האתר הישנים.

## פיתוח מקומי

נדרש Node.js 22 ומעלה. ספקו את משתני החיבור במסוף המקומי באמצעות מנגנון הסודות שלכם, ואז הריצו:

```sh
cd /workspace/shopping-list
node dev-server.cjs
```

השרת מאזין בפורט 3000; אפשר לבחור פורט אחר באמצעות `PORT`. ללא משתני מסד ניתן לעיין בקטלוג, אך עריכת הרשימה מושבתת וה־API מחזיר 503. אין לשים סודות בקובצי הפרויקט.

## בדיקות

```sh
node --check app.js
node --check api/list.js
node --check server/shared-list.cjs
node --check sw.js
```

בדיקות השרת משתמשות ב־Redis אמיתי ומבודד, דרך מתאם REST מקומי לצורכי בדיקה. נדרשים `redis-server` ו־`redis-cli`; אין צורך בחשבון Upstash או ברשת. **אין להשתמש במסד production לבדיקה זו** — הבדיקה משנה ומוחקת את המפתח של הרשימה במסד הבדיקה.

במסוף אחד, הפעילו Redis זמני בפורט כבוי וב־Unix socket פרטי, לדוגמה:

```sh
mkdir -p /tmp/shopping-list-test-redis
redis-server --port 0 --unixsocket /tmp/shopping-list-test-redis/redis.sock --unixsocketperm 700 --save '' --appendonly no --dir /tmp/shopping-list-test-redis
```

במסוף שני:

```sh
REDIS_TEST_SOCKET=/tmp/shopping-list-test-redis/redis.sock node --test tests/shared-list.test.cjs
```

אם `redis-cli` אינו ב־PATH, הגדירו גם `REDIS_TEST_CLI` לנתיב שלו. הבדיקות מכסות הוספות עצמאיות, מניעת כפילויות אטומית, הגנה ממחיקה ישנה לאחר הוספה מחדש, הסרה כפולה, קלט לא תקין, הגבלת גודל הרשימה וכשל מסד/הגדרה. אלו בדיקות מול Redis מקומי דרך מתאם; חיבור Upstash האמיתי דורש את בדיקת שני המכשירים לאחר פריסה.
